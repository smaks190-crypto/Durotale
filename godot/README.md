# Палата №0 — «Дурка»

**Годот 4.7.2 · GDScript · компактная экспериментальная 3D-глава.**

Этот проект — попытка собрать проходимую вертикальную демоверсию из сценарного брифа: палата, пост, коридор с повторяющейся дверью и соседняя палата. Три состояния одного пространства (действующее / заброшенное / искажённое), собственный ритм стука, ручка в инвентаре, две концовки.

## Как запустить исходники

1. Установить [Godot 4.7.2 Standard](https://godotengine.org/download/archive/4.7.2-stable/) для своей ОС (не .NET).
2. Открыть Godot, выбрать **Import** и указать `project.godot` в этой папке.
3. Запустить F6/F5 или нажать Play. В начале вы управляете пациентом за спиной. Если Godot сообщит об ошибках парсера, **не считайте игру готовой**: приложите журнал ошибок к следующей итерации.

На ПК: **WASD** — движение; **мышь** — обзор; **E** — взаимодействие, ритмичные нажатия у батареи, удержание у финальной двери; **Esc** — пауза. На Android: экранные кнопки движения/E, свайп справа — обзор. В настройках: чувствительность, тряска, мигание, VHS-шум.

## Что делать (без внутриигровых указателей)

Начните с палаты и короткого коридора. В стене у радиатора что-то стучит; ответьте собственным ритмом минимум из двух нажатий. Закройте форточку и оглянитесь. Дальняя дверь подозрительно возвращает вас в тот же коридор; её можно открывать **медленно**, третья попытка разрешит ситуацию. Ручка остаётся у героя. Найдите соседнюю дверь с квадратным стержнем замка, вставьте ручку. При финале можно **удерживать E у этой двери** или **уйти через пост**. Оба действия ведут к завершению и кнопке повтора.

Проверку фактической длительности нужно проводить на устройстве; временные метки не претендуют на 10–15 минут. Звуковые сигналы дублируются визуальными, поэтому глухой или выключенный звук не должен блокировать игру.

## Архитектура

- `scripts/run_state.gd` — единственный источник истины об истории, ритме стука, двери и ручке; состояние **не зависит** от визуальной версии.
- `scripts/world.gd` — геометрия помещений, физика стен и пола, три палитры, low-poly реквизит. Общие для всех вариантов коллизии.
- `scripts/player.gd` — CharacterBody3D, обзор за плечом, пружинный коллизионный кронштейн камеры.
- `scripts/hud.gd` — субтитры, минимальный HUD, пауза, доступность и экранное управление.
- `scripts/game.gd` — интеракции, стадии, звуковые тоны, смена реальности и завершение.
- `tests/check_state.gd` — логические регрессии. Запуск: `godot --headless --path . --script res://tests/check_state.gd`.
- `reference/` — **оригинальные прикреплённые пользователем изображения** для визуального ориентирования. В игре используются процедурные модели; это не полноценная реализация фотореалистичного концепта.

## Состояние сборок

Исходники создаются в ограниченном окружении. Пока не появится успешно пройденный Godot parser/import run, **проект нельзя считать подтверждённо играбельным**. Windows EXE и Android APK сюда не включены, если в корне нет соответствующих файлов `build/`.

Windows export: через Godot установите **Matching Export Templates 4.7.2**, затем Project → Export → Windows Desktop → Export Project. В папке `build/` появятся `DurkaDemo.exe` и `DurkaDemo.pck` (если не встроить PCK в EXE). Оба файла нужны для запуска.

Android export: установите Android SDK/JDK и export templates, добавьте preset Android с package identifier наподобие `org.example.durkademo`, экспортируйте debug APK. См. [документацию Godot по Android](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_android.html).

## Ограничения и честные критерии готовности

Сцена не использует внешние ресурсы или скачанные игровые модели, но **визуальная проработка пока базовая**. Сюрреалистичные состояния и низкополигональная геометрия существуют в коде; кат-сцены, анимация медсестры и реалистичный звук шагов — схематичные. Игру следует тестировать руками, прежде чем называть её завершённой. Неизвестная личность за дверью и устройство эксперимента остаются тайной.
